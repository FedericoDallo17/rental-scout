# Timbre navigation and content hierarchy

The user approved simplifying Avisos, keeping inventory diagnostics in
Administration, removing the public recruiter tour from authenticated navigation,
and making Results a dedicated, directly accessible tab.

Use the existing Patio/Manrope identity. Authenticated desktop and mobile navigation
must expose Results, saved apartments, Chimes and Alerts in the same order, with
the current destination indicated. Search editing belongs to Results. The public
tour stays available from sign-in. Admin pages retain their own active state.

Chimes starts with the user's personal matches or its empty state. Inventory
diagnostics already exist in Administration; remove the duplicate user page and
its global metrics query. Preserve matching and user isolation.

Alerts starts with the current-device activation control and concise copy.
Device instructions, optional Pushover setup, privacy and troubleshooting remain
available in native disclosures. Preserve validation, pause/resume/removal, tests,
and no-JS access to help. No real notification deliveries or scrapes are needed.

Keep in-flight onboarding, branding, filter, operation-type and provider changes.
Local implementation only; production deployment remains pending.
